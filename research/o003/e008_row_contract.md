# E008 row contract for `headroom_min_lo` (A1) and `headroom_max_hi_ind` (K1)

T0261 draft (scientist), 2026-11-09. Research note, not evidence. Code: `research/o003/headroom_metrics.py`. Tests:
`research/o003/test_headroom_metrics.py`. Patch for the founder: `research/o003/headroom_metrics.patch`, regenerated by
`uv run python research/o003/make_patch.py`. Rule source: O003 objective v5 (A1, K1, scope_in, F1, F3), D0016 and D0017.

The E008 runner writes one flat-records file (`{"schema": "mfos.rows/1", "rows": [...]}`). Both functions read **all**
rows, so a recompute entry for them has no `where` filter. They dispatch on the `kind` column and ignore any other kind,
which leaves the runner free to add its own row kinds. All values are SI: inductance in H, temperature in K.
Booleans are JSON `true`/`false`. A number given as a string is rejected for the boolean columns.

## 1. Row kinds and columns

### `kind = "reference"`: one row per reference, admissible or not
| column | unit / type | required | meaning |
|---|---|---|---|
| `reference_id` | str | always | vault id or public case name |
| `admissible` | bool | always | scope_in admissibility, decided before any solve. `false`: no other rows are needed, and the reference is never counted |
| `L_term_H` | H, ≥ 0 | admissible | the per-reference terminal inductance fixed in the spec (7e-9 for public references) |
| `on_grid` | bool | admissible | reference already on the 0.5 mm grid. If true, s_ref = 0 |
| `L_snap025_H`, `L_snap05_H` | H | when `on_grid` is false | L_sub of the reference snapped to 0.25 mm and to 0.5 mm, both at 0.25 mm cells |
| `L_snapchk0125_H`, `L_snapchk05_H` | H or null | key present when `on_grid` is false | pre-registration snapping check: snapped to 0.125 mm and to 0.5 mm, both at 0.125 mm cells. Use null for both if the check was not completed. Setting only one raises |
| `L1_min_first5000_H`, `L1_min_all_H` | H | admissible (K1) | lowest L1 among the first 5,000 and among all 20,000 candidates of the sealed sequence. If first < all, the rows are inconsistent and the function raises |

### `kind = "layout"`: one row per inductance-solved layout
| column | unit / type | required | meaning |
|---|---|---|---|
| `reference_id`, `layout_id` | str | always | `layout_id` must be unique within its reference. Ties in L_sub are broken by `layout_id` (string order) |
| `role` | str | always | `"twin"` (exactly 1), `"reconstruction"` (exactly 1), `"candidate"` (exactly 16: the D0008 shortlist). The functions ignore other roles (for example `"degraded"` and `"control_best"` for F1(b)) |
| `L_sub_H` | H | always | L_sub at 0.25 mm cells, production layers and wires. This is the metric's `pred` column |
| `L_sub_c05_H` | H | band rows | 0.5 mm cells, layers 10/6/6, production wires |
| `L_sub_thk_c_H` | H | band rows | 0.5 mm cells, layers 5/3/3 |
| `L_sub_thk_f_H` | H | band rows | 0.5 mm cells, layers 20/12/12 |
| `L_sub_wire_f_H` | H | band rows | 0.5 mm cells, 10/6/6, wire annuli bisected, 12 filaments per ring |
| `L_sub_null_H` | H | every row of every kind (see §3) | the declared A1 null predictor |

**Band rows**, the layouts that need all four 0.5 mm columns: the twin, the reconstruction, the inductance-only best (the
lowest `L_sub_H` candidate), the A1 best, and every K1 near-tie candidate. On any other candidate these columns may be
missing or null. A needed band value that is missing raises.

### `kind = "die"`: one row per die of every thermally checked layout
| column | unit / type | required | meaning |
|---|---|---|---|
| `reference_id`, `layout_id`, `die_id` | str | always | `(layout_id, die_id)` must be unique within its reference |
| `Tj_l0_K`, `Tj_l1_K`, `Tj_l2_K` | K | always | per-die Tj max (maximum nodal value on the die top face) at thermal levels 0, 1 and 2 of **that layout's own** grids. GCI = `gci_capped(l0, l1, l2, floor)` |

**Die count.** scope_in fixes the die count, so every thermally checked layout (the twin, the reconstruction and each
candidate F3 checks) must carry exactly as many die rows as the twin. Any other count raises (fail closed), in both
metrics for the reconstruction and in `headroom_min_lo` for candidates. Layouts F3 does not check are not looked at.

Die rows are required for the twin and the reconstruction (F1(a2)) and for every candidate that F3 checks. The function
recomputes F3's checked set itself: candidates in ascending `L_sub_H` order, in batches of 4, stopping after the first
batch that holds a candidate meeting the conservative test, at most 8. Die rows of other layouts are ignored, so the
L1-only null's extra thermal checks cannot become the A1 best.

## 2. What each function computes (rule order)
Both functions build the same per-reference record (`headroom_per_reference`). A reference is **counted** if it is
admissible and passes F1(a1) and F1(a2):

- (a1): |1 − L(W)/L(ref)| ≤ 2 e_R(W, ref) + s_ref.
- (a2): |max T(W) − max T(ref)| ≤ G(W) + G(ref).

`headroom_min_lo` returns the minimum of h_lo over counted references. `headroom_max_hi_ind` returns the maximum of h_hi
over counted references. With no counted reference, both raise, so E008 is INVALID (F1).

- **e_R(X, C)**: R = L(X)/L(C) at each of the five levels, then
  3|R(0.25) − R(0.5)| + middle(R(5/3/3), R(0.5), R(20/12/12)) + 3|R(wire) − R(0.5)|. This is P3's estimator; `middle`
  is checked against `o006_p3_em_convergence.middle_term` in the tests.
- **s_ref**: 0 on grid. Otherwise 2|L_snap025/L_snap05 − 1|, raised to |L_snapchk0125/L_snapchk05 − 1| if that is larger.
- **a** = L(C)/(L(C) + L_term), where C is the comparator (the twin).
- **A1**:
  1. Run the F3 checks, testing every candidate against **W** with the conservative test
     max_i(T_i + GCI_i)(C) − max_j(T_j − GCI_j)(W) ≤ 2 K. A +inf GCI makes the upper bound +inf and drops out of the
     lower bound.
  2. Apply the twin rule: with no eligible candidate, or L(W) ≤ L(best), h_lo = −a s_ref.
  3. Otherwise h_lo = a(1 − r(1 + 2e_R + s_ref)).
- **K1**:
  1. Levelling: if L1_first ≤ (1 + w_lev) L1_all is false, then h_hi = +inf. Here w_lev = 2 e_R(ind, W) + s_ref.
  2. Twin rule: if L(W) ≤ L(ind), then h_hi = a s_ref.
  3. Near ties: take the candidates with L ≤ (1 + w_ind) L(ind). h_hi is the largest of
     a(1 − r_c(1 − 2e_R(c) − s_ref)).

  K1 never reads candidate die rows. Over references K1 takes the maximum, so a single counted reference that is not
  levelled makes K1 = +inf, and K1 cannot fire (tested).

## 3. Spec entries the runner and the spec should use
- Primary: `{metric: headroom_min_lo, fn: headroom_min_lo, pred: L_sub_H}` and
  `{metric: headroom_max_hi_ind, fn: headroom_max_hi_ind, pred: L_sub_H}`. Defaults: `floor` 1e-3 K, `tj_limit_K` 2.0.
  State both explicitly in `params` for readability. Both metrics raise, before reading any row, on a `floor` that is
  null, not finite or negative and on a `tj_limit_K` that is null, not finite or not positive (T0276). Before T0276 a nan
  `tj_limit_K` gave A1 = -a s_ref without raising, and an infinite `floor` zeroed every GCI, so a divergent candidate
  became eligible.
- Sensitivity (reported, not criteria): the same entries under new metric names with `params: {L_term_H: 0.0}` and
  `{L_term_H: 1.75e-8}`.
- Reconstruction-based secondary: `params: {comparator: reconstruction}`.
- Declared A1 null: `{name: twin_as_best, kind: column, column: L_sub_null_H, applies_to: [headroom_min_lo]}`.
  `mfos.metrics.null_column` calls `float(row[column])` on **every** row passed to the metric, and a null spec has no
  `where` filter, so **every row of every kind the runner writes must carry a finite `L_sub_null_H`**. A row without it
  makes the whole recompute entry fail (closed, but it costs a run). The value, by row kind:
  - `layout`, role `candidate`: the twin's `L_sub_H` of that reference (the null "twin as best");
  - `layout`, roles `twin` and `reconstruction`: their own `L_sub_H`, so the twin gates are unchanged;
  - `layout`, any other role (`degraded` and `control_best` of F1(b), the extra layouts of the L1-only null, any role the
    runner adds): their own `L_sub_H`. The metrics ignore these rows (tested), so the value is never used;
  - `die` rows, including the extra thermal rows of the L1-only null: the twin's `L_sub_H` of that reference (unused);
  - `reference` rows: the twin's `L_sub_H` of that reference (unused; `10e-9` if the reference is inadmissible and has no
    twin row);
  - any other row kind the runner adds (it has no `reference_id` to look up): `1e-8`, an arbitrary finite number, unused.

  The alternative to a value is a recompute entry that excludes the rows, which this contract does not offer: the two
  headroom metrics read all rows and the null cannot filter. The null then gives h_lo = −a s_ref ≤ 0 and fails A1 by
  construction, as the objective says. The candidates' thermal rows are not needed for this, because the twin rule is
  decided first. Under the null every candidate has the twin's L_sub, so F3's order falls back to `layout_id` and its
  first batch may be candidates the real run never checked thermally. The twin rule (L(W) ≤ L(c), equality included)
  decides before any of their die rows are read. Tested in
  `test_o003_twin_rule_needs_no_candidate_dies_also_under_the_declared_null`, and with extra degraded, control_best,
  L1-null and runner rows in `test_o003_null_column_contract_for_extra_row_kinds`.
- Runner: compute both metrics with these functions (import them once the patch is applied, or from the draft), so
  that runner and evaluator agree within `rel_tol` 1e-9. K1 may legitimately be +inf (`mfos` serialises it as Infinity).

## 4. Not in these functions (runner sanity checks)
The runner gates these itself:

- F1(b): the planted-headroom control;
- F1(c): w ≤ 0.05 (the per-reference record gives `w`, `w_ind` and `w_levelling`);
- F6(a)–(e): the thermal provenance, node counts, GridRule hash, energy balance, calibration and stack spot check;
- that F3's thermal checks really ran in the order the function assumes;
- the provenance of the two L1 minima.

The per-reference record also gives `n_thermal_checked`, `n_tj_rejected`, `n_tj_inf`, `checked_ids`, `best_id`,
`ind_id`, `near_tie_h_hi` and the optimistic-test secondary `h_opt_hi`. `h_opt_hi` is None when that candidate has no
band solves.

## 5. Interpretations made in this draft, for the founder (facts vs choices)
1. **+inf G in F1(a2).** Taken literally, a twin or reconstruction die with GCI = +inf passes the thermal twin gate
   (|Δ| ≤ inf). The objective does not say otherwise. A1 stays safe: that twin die drops out of W's lower bound, so
   candidates find the conservative test harder to pass.
2. **Orientation of the snapping check's relative difference.** The draft uses |L(0.125-snap)/L(0.5-snap) − 1|, the
   same orientation as s_ref's own term. The other orientation differs only at second order.
3. **Snapping check not completed.** Null values leave s_ref at its first term. The objective routes this case to the
   founder before registration.
4. **Reconstruction-based secondary.** The comparator in a, r, e_R, the twin rule and the near-tie band is replaced by
   the reconstruction. Two things do not change: the Tj test stays against W, so the feasible set cannot move (scope_in),
   and levelling keeps the twin pair's w (it is a property of the search).
5. **Near ties.** The near-tie set holds shortlisted candidates only; the twin is not a member. Including the twin could
   not change the maximum: when the inductance-only best has r < 1, its h_hi ≥ a s_ref whenever s_ref ≤ 1.
6. **Twin rule versus thermal rows.** If the comparator's L_sub is at most every shortlisted candidate's, A1 is decided
   by the twin rule without candidate die rows. Otherwise any missing die row that F3 needs raises.
7. **Ordering and ties.** Ascending `L_sub_H`, with ties broken by `layout_id`. The runner must use the same order for
   F3.
8. **Levelling threshold under the twin rule (T0266 note 1).** Levelling is decided before the twin rule, with
   w_lev = 2 e_R(ind, W) + s_ref. When the twin rule then decides K1 (L(W) ≤ L(ind)), the rule's "e_R = 0" would give the
   stricter threshold (1 + s_ref). The code keeps the first reading, because the objective puts levelling first and
   levelling is a property of the search. Founder: confirm, or ask for (1 + s_ref) whenever the twin rule applies.
9. **Switches in the reconstruction-based secondary (T0266 note 2).** With `comparator: reconstruction`, these quantities
   switch from the twin to the reconstruction: a = L/(L + L_term), r, e_R in A1's w, the twin rule's comparison, the
   near-tie band and each near-tie candidate's w. These do not switch: the Tj test (candidates are tested against W), the
   levelling pair (ind, W), the F1 gates and the F3 order. The objective's A1 text only says "r against L_sub of the
   reconstruction", so a, e_R and the twin rule switching is a choice. It affects secondary columns only. Tests pin each
   of these switches: a and r (`test_o003_sensitivity_and_reconstruction_based_secondary`), e_R in A1 and K1, the Tj
   test against W and the levelling pair (`test_o003_reconstruction_secondary_uses_the_reconstruction_pair_but_the_twins_tj_and_levelling`),
   the twin rule and the near-tie band (`test_o003_reconstruction_secondary_switches_the_twin_rule_and_the_near_tie_band`).

## 6. How the tests are checked (T0269)
`research/o003/check_mutants.py` applies 110 textual mutants of `headroom_metrics.py` in memory, one at a time, and runs
`test_headroom_metrics.py` against each. It exits 0 only if every mutant fails at least one test. The list includes
T0266's eleven survivors (T0266 names ten of them; the eleventh is reconstructed, see the script's header), 54 mutants
added in T0269 attempt 1, 36 from attempt 2's independent probe, and 9 from T0276. Seventeen of attempt 2's 36 survived
attempt 1's tests and are killed by the section "T0269 attempt 2 gaps". One of the 17 decided a criterion: K1 taking the
minimum instead of the maximum over references. Negative control: with attempt 1's test file the script reports exactly
those 17 and exits 1. T0276's nine are review T0275's two surviving probes (F3's missing-die-rows shortcut keyed to the
batch's first candidate instead of `order[0]`; the optimistic column without its twin rule), two more on that twin rule
(strict comparison; compared against the twin under `comparator: reconstruction`), and five on the parameter-value
guard. All nine survive the T0269 test file (commit 3ab1197c) and are killed by the section "T0275 gaps (T0276)"; the
T0276 tests, run against the T0269 draft, fail in exactly the 22 parameter-value cases. Each fail-closed case must raise its own guard's message (`_MATCH`), so an unrelated ValueError cannot pass
it. Mutation testing shows only that the tests detect these specific edits. It does not show that the rule text is
read correctly; that rests on the hand values and on T0266's independent implementation.
