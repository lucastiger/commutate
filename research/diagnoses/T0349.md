### 2.2 Competing explanations and discriminating tests

**H-A (implementation): the check or the control selection is computed wrong.** Candidate mechanisms: wrong band
index, inductance_best not the minimum, shortlist not the 16 lowest-L1 candidates, or mixed bases with the terminal
inductance L_term included on one side only. The last one was worth testing: module-level h_plant would be 0.158,
which is close to the observed 0.161.

- Test 1: recompute from the raw checkpoints. Result: identical. The control best is the minimum of its 16 L2 solves.
  The 16 solved candidates are exactly the 16 lowest-L1 fingerprints of the control stream (the same holds for the
  main stream).
- Test 2: read the code (`e010_run.evaluate` lines 2252-2256; `search.run_control`). h_plant and h_ctrl both use
  `bands[…][0]`, which is L_sub. With L_term = 7 nH on both sides the control still fails: h_ctrl_mod 0.116 vs
  h_plant_mod 0.158. The 0.158 vs 0.161 closeness was a coincidence from comparing different bases.
- **H-A rejected** [fact].

**H-B (model or implementation in L2): W's L_sub is too low because of a solver artefact.** Example: W's overlapping
slot and column rectangles counted twice.

- Test: compare W with the reconstruction. W's L2 equals the reconstruction's L2 to 3e-14, and W's copper per net
  equals the reconstruction's (`twin_copper` symdiff 0 mm²). L1 (numpy PEEC, `twin._l1`) is a separate method. It
  also puts W below every one of the 40,000 candidates of both streams.
- **H-B rejected** for the overlap mechanism [fact].
- Not ruled out: an L2 bias common to all of W's full-width strips that L1 shares. Both models agree on the ordering,
  so this would need a shared error [inference: unlikely].

**H-C (experimental, multi-fidelity ranking): L1 misranks on 2R, so the 16-candidate L1 shortlist misses candidates
that are good at L2.**

- Test: L2/L1 ratio over the 32 L2-solved candidates. Result: 1.228 to 1.290, against the twin's 1.244.
- To pass, a control candidate needs L2 ≤ 1.0172 L_W. The control stream's best L1 is 1.0622 L1(W), so such a
  candidate would need L2/L1 ≤ 1.191. That is 3 % below the lowest of the 32 observed ratios.
- **H-C not supported** as the main cause [inference]. Pearson r(L1, L2) is only 0.45 to 0.60 within the shortlists,
  but the shortlists span a narrow L1 range (range restriction).

**H-D (experimental, search power and sampler support): the frozen sampler (`derivative._sample` plus DRC rejection)
puts almost no probability near W on 2R, and W itself is outside its support. A 20,000-draw random screen therefore
cannot reach the twin's level.**

- Test 1, L1 tail of the run's own pools [fact]. All 20,000 fingerprints in each stream are unique, but all draws
  share one topology (T0341). Within 2 / 3 / 5 / 7 / 10 / 15 % of L1(W): main 0 / 0 / 1 / 3 / 23 / 184, control
  0 / 0 / 0 / 2 / 23 / 199. The minimum excess is 3.05 % (main) and 6.22 % (control).
- Test 2, parameter support [fact] (`sampler_support.py`). W rebuilt from its own vector is DRC-clean, passes
  `_quick_ok` and reproduces its fingerprint, so it is a valid point of the parameter space. Across the 40,000
  DRC-valid run candidates, W lies outside the drawn range in 13 of 36 geometric coordinates (e.g. `slot0_u0`: W 7,
  drawn [12, 19.5]; `slot1_u1`, `slot3_u1`: W 47, drawn [37, 41]). The nearest candidate is 83 mm away from W in
  Manhattan distance, against 44 mm for D.
- Why [fact, code and module docstring]: `_sample` builds every slot from its column's inner edge outward
  ("the slots attach to the column's inner edge"). W's DC− and DC+ slots straddle their columns (u 7 → 47 and 7 → 33
  around columns at u 9 to 12), and its PHASE slots overlap the PHASE column. 50,000 raw proposals (645 non-None):
  none has a straddling slot. So `build()` accepts W, but `_sample` cannot produce it.
- Test 3, copper rather than parameters [fact] (`attached_twin.py`). W rewritten in the sampler's attached form
  (4 mm² and 3 mm² copper difference on DC+ and DC−, PHASE identical) is DRC-clean with L1 = 0.998 L1(W). It needs
  the PHASE column's outer edge at u = 47 mm, which `_sample` cannot draw. The sampler sets c1 = pad edge + U(0, 1.5),
  and the largest value drawn in the run was 45.5 mm. With that edge at 45.5 mm the layout is still DRC-clean and
  L1 = 1.018 L1(W).
- [inference] Two separate shortfalls, each enough to fail the control:
  - (i) Support. The sampler's construction keeps the closest twin-like copper at about +1.8 % in L1. The pass margin
    is +1.7 % in L2, so even an exhaustive search of the support could only pass narrowly by this route.
  - (ii) Prior mass. The +1.8 % point beats all 40,000 draws, whose best is +3.05 %. So the random prior's lower tail
    on 2R is far thinner than the 20,000 budget needs.
- [speculation] A power-law fit to the tail counts (N(≤x) ∝ x^5.5 between 5 % and 15 %) puts the expected number of
  DRC-valid draws needed for one candidate within 1.7 % at about 1e7, roughly 700 times the budget. The tail may
  instead end above 1.7 % because of (i).
- **H-D supported** by every test.

**H-E (infrastructure): the phase A/B split or the VM resume corrupted state.**

- Test: provenance. `run_manifest.json` config and seed hashes, and the solve fingerprints, are consistent; W's
  rebuilt fingerprint equals the recorded one. F1(b) uses only phase-A EM solves, and phase B ran only the thermal
  fv3 spot check.
- **H-E rejected** [fact].

**What would have proved H-D wrong:** a control or main candidate with L1 within about 2 % of W, or a W-equivalent
layout that the sampler cannot produce, built at L1 well below 1.0. Neither appeared.

## 4. Conclusion

- **Failure class: experimental** (confidence 0.85), matching O003's frozen consequence for F1b_control_fails.
- **Root cause.** On 2D_Case_2R, the only counted reference, the frozen D0008 instrument has no power near the
  reference's own design, so the planted-headroom control cannot be passed:
  - the generator sampler builds slots only from a column's inner edge outward;
  - the PHASE column's outer edge can reach at most 45.5 mm;
  - the 20,000-draw random screen therefore comes no closer than 3.05 % (main) and 6.2 % (control) to the twin at L1;
  - the control needed to come within 1.72 % at L2.

  The driver and the check are computed correctly. The control did its job: it stopped a K1 kill based on a search
  that could not reach the reference designer's level. Read E010's h = 0 as "not found by this search", never as
  evidence that 2R has no headroom.
- **Secondary, independent: implementation** (confidence 0.9). The evaluation report was registered under a path
  the evaluator cannot resolve for burst-VM runs.
- Confidence is not higher because: L2 was solved on only 32 candidates (H-C cannot be fully excluded); the support
  argument for the +1.8 % variant is at L1 only and was not checked through `_sample`'s full joint constraints; and
  a shared L1/L2 bias (H-B residual) was not checked against an external solver.

## 6. What would change this conclusion

- An L2 solve (or a FastHenry cross-check, D0002) of the attached-form W variants, or of the unsolved control
