- 2026-09-30 PyYAML (used by mfos to load specs) follows YAML 1.1: an unsigned exponent such as `5.0e6` parses as the string '5.0e6'. Write `5.0e+6` in spec configs and type-check config values in the runner (E001 `checked_config`). (source: T0041)
- 2026-09-30 scipy `integrate.quad` defaults to epsabs=1.49e-8, which exceeds SI inductance integrals (~1e-8 H). Always pass `epsabs=0` with an explicit epsrel; with the default, a log-singular integrand came out 1.1e-4 low (b1_exact_limits.py). (source: T0041)
- 2026-10-01 A correction derived for one term of a kernel applies to every term that uses that kernel: the round-wire mean-distance (AMD) shift was fixed for self terms but not for wire-wire and wire-image mutuals (B3 M12 3.9-7.8e-4 off against a stated 1e-6). When correcting a closed form, grep every call site of the kernel. (source: T0041, reviews T0051/T0052)
- 2026-10-01 A geometric (constant-ratio) refinement-error estimate underestimates when the observed contraction ratio grows (additive refinement, emerging slow mode); require a constant refinement ratio and test the ratio trend over >= 4 levels before using Roache's 1.25. (source: T0041, review T0052)
- 2026-11-02 Do not apply a three-grid GCI to a bilinear interpolant sampled at a fixed off-lattice point on bisected cell-centred grids: the stencil coordinate follows xi -> (2 xi + 1/2) mod 1, so the interpolation error -1/2 xi(1-xi) h^2 T'' has no C h^p expansion and the GCI reports "divergent" for a field that converges at order 2 (E006 A4 = inf from three reference-max points; only xi = 1/2, a persistent grid line, is safe). (source: T0198)
- 2026-11-02 A per-layer cell count (thermal Z_CELLS = 2) is not a resolution: on a 10 mm plate it leaves dz = 1.25 mm at level 2 and 0.12-0.14 K of through-thickness error (Muzychka Cases 1a/2), invisible on thin DBC stacks. Bound cell sizes in absolute terms and test every reference case's thickness regime before freezing a grid rule. (source: T0198)
- 2026-11-04 Size burst VMs by memory, not cores: thermal_fem and thermal_fv run one solve at a time on one core (100-110 % CPU on a 16-vCPU VM), so E2, the cheapest GCP memory, with its core count set by its 8 GB/vCPU cap, is the minimum (e2-highmem-16 at $0.73/h ran the O007 L2 levels 1-3 in 62 min; n2-highmem-32 is $2.10/h). GCP machine "GB" are GiB: a 128 GB machine has 137e9 B and 135e9 B usable, so a "needs 122 GB physical -> 256 GB machine" sizing that read 128 GB as 128e9 B doubled the cost. (source: research/o007_l2/full.json, founder bursts 2026-11-04)
- 2026-11-04 The FV L2 peaked at 1.20 kB/cell at level 3 (69.9 GB for 58.1 M cells, 43.3 GB for 35.9 M cells), below E006's preflight 1.5 kB/cell and the level-1-measured 1.78 kB/cell: size level-3 VMs from the level-3 rate, keeping E006's preflight as the refusal rule. (source: research/o007_l2/full.json)
- 2026-11-04 scikit-fem bases built per chunk still do whole-mesh work: every basis maps all elements to DOF coordinates unless built with `disable_doflocs=True`, and `basis.interpolate` splits the vector by `np.unique` over the global `Dofs.element_dofs`. Chunked assembly therefore cost O(N^2 / chunk): the O007 probe's 13.6 M-DOF Q1 solve spent over 100 min in one assembly. Pass `disable_doflocs=True` and use `thermal_fem._interpolate`; time a chunk at two mesh sizes before trusting a chunked loop. (source: commits 0929d9e and its follow-up, probe burst 2026-11-04)
